# Equivalent-mutant ledger for narrativetrace-skills-catalogue's Tier B eval runner, read by
# `poe mutate-skills-gate` (scripts/mutation_gate.py, invoked with the
# "narrativetrace-skills-catalogue" argument).
#
# Same format as mutation/equivalents.txt: one line per mutant, the mutmut mutant id (as printed
# by `mutmut results` from packages/narrativetrace-skills-catalogue), a tab, then a one-line reason
# a human can review. A mutant listed here is excluded from the gate's denominator -- it can never
# be killed because the mutated code is behaviourally identical to the original, not because the
# test suite has a gap. Every entry must be re-verified (`mutmut show <id>`, run from
# packages/narrativetrace-skills-catalogue) before being trusted; do not add an entry just because
# a mutant survives.
#
# Scope: only evals/run.py, quota.py, platform_presets.py, tier_precondition.py -- see
# packages/narrativetrace-skills-catalogue/pyproject.toml's [tool.mutmut] source_paths. Case
# content (prompts, fixtures, graders, trigger sets, YAML/JSON) is data and is never mutated; that
# is a structural exclusion (mutmut only mutates the four listed .py files), not something to list
# here.
#
# Empty as of this file's creation: the first `poe mutate-skills` run (2026-09-13) measured an
# 83.0% kill rate (399/481), comfortably above the 80% floor with zero exclusions, and its 82
# survivors have not yet been triaged one by one. Add entries here only after that triage confirms
# a specific survivor is genuinely equivalent, not merely uncovered.
#

# distribution this ledger covers was renamed narrativetrace-skills -> narrativetrace-skills-
