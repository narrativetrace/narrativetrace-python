# 应提交的内容

两个类别,而不是一个。NarrativeTrace 写出的几乎所有内容都是**描述单次运行的生成产物**——你配置的
输出目录下的任何内容都不是源代码,因此都不属于版本控制。唯一的例外是**已批准的追踪**
(`.approved.nt`):它经过人工审阅并被接受为行为契约,就像快照测试的
golden file 是一项决策,而不是输出——完整的语法和审批模式的工作流见
[结构化追踪格式](结构化追踪格式.md)页面。

| 产物 | 路径模式 | 是否提交? | 原因 |
|---|---|---|---|
| 追踪文件(Markdown,默认格式) | `<OUTPUT_DIR>/traces/<Class>/<slug>.md` | 否 | 每次运行都会重新生成 |
| 追踪文件(`text`/`mermaid`/`plantuml` 格式) | `<OUTPUT_DIR>/traces/<Class>/<slug>.{txt,mmd,puml}` | 否 | 每次运行都会重新生成 |
| JSON 场景文档(仅 Markdown 格式) | `<OUTPUT_DIR>/traces/<Class>/<slug>.json` | 否 | 与规范 JSON 是同一个追踪——每次运行都会重新生成 |
| Mermaid 图表附件(仅 Markdown 格式) | `<OUTPUT_DIR>/diagrams/<Class>/<slug>.mmd` | 否 | 每次运行都会重新生成 |
| 规范条目数组 | `<OUTPUT_DIR>/traces/<Class>/<slug>.canonical.json` | 否 | 供一致性校验/其他实现使用的机器产物,通过 `NARRATIVETRACE_CANONICAL` 按需开启 |
| 结构化追踪(`.nt`,最近一次绿色基线) | `<OUTPUT_DIR>/structural/<Class>/<slug>.nt` | 否 | 每次绿色运行都会重新生成——这是*本地*工作副本,不是下面那份经过审阅的基线 |
| **已批准的追踪** | `<APPROVED_DIR>/<Class>/<slug>.approved.nt` | **是**,一旦你启用审批模式 | 经过审阅的行为契约——是一项决策,而不是输出 |
| 已接收的追踪 | `<APPROVED_DIR>/<Class>/<slug>.received.nt` | 否 | 在出现差异时写出(或者还没有基线时),供审阅使用;通过 `uv run poe approve` / `narrativetrace-approve` 提升,绝不提交 |
| 不完整的追踪 | `<APPROVED_DIR>/<Class>/<slug>.incomplete.nt` | 否 | 当本次运行本身就不完整时,写出这个文件来代替已接收的追踪;approve 动作按名称忽略它 |
| `manifest.json` | `<OUTPUT_DIR>/manifest.json` | 否 | 每次运行都会重新生成——是对上面这些产物的一份索引,本身不是基线;它顶层的 `run` 对象(`id`、`name`——运行自己的三词短语)命名的是*这一次会话*,而不是某个场景,所以即使其他一切都没变,它也会在每次运行时改变 |
| 套件清晰度报告 | `<OUTPUT_DIR>/clarity-report.md` | 否 | 生成的报告,不是决策 |
| 套件清晰度结果 | `<OUTPUT_DIR>/clarity-results.json` | 否 | 与报告一同生成 |
| 独立扫描器输出(`narrativetrace-clarity` CLI) | `--output-dir` 指向的任意位置 | 否 | 与上面相同,按需生成 |
| `glossary.json` / `glossary.md` | 仓库根目录(或你通过 `NARRATIVETRACE_GLOSSARY_DIR` 指向的位置) | **是**,如果你使用它 | 人工维护的词汇表——提交的文件就是清晰度评分读取的内容,并且从不会被测试运行重新生成。"一个文件,一个评审流程" |
| `.claude/skills/**/SKILL.md`、`AGENTS.md` 中的 `<!-- narrativetrace:skills:* -->` 区块 | `.claude/skills/{add-narrative-tracing,narrativetrace-doctor}/SKILL.md`、`AGENTS.md` | **是** | 由 `narrativetrace-skills-catalogue` 的类型化目录生成的构建产物(`python scripts/skills_render.py --fix`),不是测试运行产生的输出——像 `glossary.json` 一样提交:重新生成、在差异中评审,并通过漂移检查(`python scripts/skills_render.py --check`,集成在 `uv run poe check` 中)而不是手工编辑 |
| `.agents/skills/**/SKILL.md`(检测到时也包括 `.claude/skills/**`)、`AGENTS.md` 中的 `<!-- narrativetrace:start … --> … <!-- narrativetrace:end -->` 区块、`CLAUDE.md` 里的一行 `@AGENTS.md` | `uv run narrativetrace init` 在*你的*项目里写入的任何位置(不是上面这条本仓库自己的开发副本) | **是** | 和 `glossary.json` 一样"先评审、再提交"的形态:`init --dry-run` 展示 diff,人工评审,`init`(不加该选项)写入。每一页安装好的文件都带有一行来源说明 `<!-- installed by narrativetrace init from <coordinate> — edit the catalogue, not this file -->`,注明它来自哪里;`narrativetrace doctor` 的 `config.skills-installed` 检查会读取这个印记,在后续版本使其过期时提醒你,而 `narrativetrace uninstall` 只会移除 `init` 写入的内容(带标记的区块、带来源说明的页面、`CLAUDE.md` 里的那一行),不会动你自己在周围添加的任何东西 |
| `skills-lock.json` | 项目根目录,`npx skills add` 运行的地方 | **是**,如果你的团队使用那个工具 | 注册表自己的锁文件(来源、内容哈希)—— 像提交你工具链依赖的任何其他锁文件一样提交它 |
| `.claude-plugin/marketplace.json` | 本仓库自己的根目录 | **是** | 本仓库自己的 Claude Code 插件清单,从类型化目录渲染而来(`python scripts/skills_render.py --fix`)—— 已提交的构建产物,从不手工编辑,按与上面技能页面相同的方式进行漂移校验 |

个人插件安装(`/plugin marketplace add …`、`/plugin install …`)落在你自己的插件缓存里,在任何
项目之外——这里没有东西需要提交。

默认的 `<OUTPUT_DIR>` 是 `narrative-traces`,默认的 `<APPROVED_DIR>` 是 `test-narratives`
(两者都相对于套件运行时所在的目录,两者都可配置——见[配置指南](配置指南.md));把输出目录以及
审批目录下那两种未批准的追踪模式都加入忽略列表:

```gitignore
narrative-traces/
test-narratives/**/*.received.nt
test-narratives/**/*.incomplete.nt
```

如果你把 `NARRATIVETRACE_OUTPUT_DIR`/`NARRATIVETRACE_APPROVED_DIR` 指向别处——一个 `build/`
目录、一个 CI 产物文件夹——就改为忽略那些路径。`glossary.json` 和一份已批准的追踪是这份清单中的
两个例外:它们是人编写(或审阅并接受)的文件,一次运行只会*读取*它们,绝不会覆盖——这正是让它们
成为源代码的原因。

## 一句话总结这条规则

如果一个文件的存在仅仅是因为跑了一次测试,那它就是输出——不要提交它。如果一个文件的存在是因为
一个人审阅并接受了它,那它就是一份基线——提交它。`glossary.json` 和 `.approved.nt` 是这份清单中
唯一两行由人编写或接受的内容;其余一切都是重新生成的。

## 审批模式,直观呈现

```text
测试通过
   |
   v
把当前结构与已批准的追踪进行比较
   |
   +-- 相同 --> 通过,不写出任何内容
   +-- 不同 --> 写出一份已接收的追踪并失败
                |
                v
           一个人审阅这份差异
                |
                v
        uv run poe approve  (或 narrativetrace-approve)
                |
                v
        .approved.nt 已更新,提交它
```

`.approved.nt` 永远不包含参数或返回值——完整语法见[结构化追踪格式](结构化追踪格式.md)。
