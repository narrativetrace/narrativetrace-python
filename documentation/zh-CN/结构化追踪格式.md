# 结构化追踪格式(`.nt`)

*(since 0.1.2, unreleased)*。面向 AI 安全的结构化追踪产物(产品 ADR-002):每个测试场景一个
文件,只包含开发者编写的行为*形状*——零运行时值。这个格式是**跨平台**的:每一个 NarrativeTrace
实现都会发出完全相同的格式,这正是让已批准的追踪和一致性夹具能够在各平台之间流通的原因。本页
反映的是参照实现自身的结构化格式规范——下面的语法是规范性的,并且在本产品发布的每一种语言中
都完全一致。

## 文件与命名

| 文件 | 角色 |
|---|---|
| `<output_dir>/structural/<TestClass>/<slug>.nt` | 与 Markdown 追踪一起写出;磁盘上的这个文件是**最近一次绿色基线**——一次非绿色的运行会与它比较(控制台差异、失败报告),但绝不会覆盖它。"绿色"是整体判定:一个测试通过了、但其结构被审批模式*拒绝*的运行,最终判定为非绿色,因此一个被拒绝的结构永远不会成为基线,回退这次变更也不会报告任何差异 |
| `<approved_dir>/<TestClass>/<slug>.approved.nt` | 已提交的已批准追踪(通过 `NARRATIVETRACE_APPROVAL=true` 按需开启,目录可通过 `NARRATIVETRACE_APPROVED_DIR` 配置,默认为 `test-narratives`)——一个通过、但结构不同的测试会带着可读的差异失败 |
| `<slug>.received.nt` | 在出现差异时(或者还没有已批准的追踪时)写在已批准的追踪旁边;审阅它,然后通过 `uv run poe approve` 或 `narrativetrace-approve` 控制台脚本提升它 |
| `<slug>.incomplete.nt` | 内容相同,但当本次运行本身就不完整时(尽力而为路径丢弃了事件,或者因触及采纳上限而拒绝了一个 async scope),会写出这个文件来代替 `.received.nt`。approve 动作按名称忽略它:一次不完整的运行绝不能成为已提交的基线,否则每一次后续的完整运行都会被读作*新增*了调用。这样的运行按子序列包含关系比较,而不是按相等比较——缺失会被容忍并被具名标出,任何新增或重新排序的内容依然会失败 |

格式扩展名放在最后(`.approved.nt`,ApprovalTests 的约定),这样编辑器和 diff 查看器就能通过
`.nt` 识别它。注意:`.nt` 在某些语法高亮映射中与 RDF N-Triples 冲突;在需要的地方于
`.gitattributes` 中注册一个覆盖规则。

### 产物身份(跨平台)

上面的 `<slug>` 是一次测试调用的**产物身份**,每个实现都用相同的方式拼写它——一个实现写出的
产物,在另一个实现里也能用同样的名字找到:

- 一个普通的测试方法就是它自身转换为 slug 后的名字:按驼峰式和 `_` 拆分,转为小写,把
  `[a-z0-9_]` 以外的所有字符替换为 `_`——`customerPlacesOrder` → `customer_places_order`。
- 一个会运行多次的测试(任何 `@pytest.mark.parametrize` 用例,或者一个参数化 fixture)的某一次
  调用,会追加 `-<index>-<label>`:以 1 为起点的调用序号,补零到三位数,后面跟着这次调用的可读
  标签——同样经过 slug 规则处理,连续的 `_` 会被折叠,两端会被裁剪——
  `equipment_can_be_found-002-find_tent`。一个转成 slug 后为空的标签会被丢弃,只留下
  `equipment_can_be_found-002`。
- 之所以用 `-` 作分隔符,恰恰是因为 slug 的字母表里不可能产生这个字符。让这套方案不会冲突的
  关键是索引——而不是标签:两次调用永远在索引上不同,所以那些仅在路径无法承载的字符上有区别的
  标签,依然会得到各自独立的文件。标签的作用则是让名字变得可读。
- 这个名字在多次运行、多台机器、多个进程之间都是稳定的,这正是让一次调用的 `.approved.nt`
  可以被提交到版本控制的前提。当名字超出单个路径元素 255 字节的限制时,*方法*那一半会被截断,
  并附加上对完整 slug 做 Java `String.hashCode` 得到的八位十六进制字符——这是规范定义的,因此
  在任何地方都完全一致;如果用按进程生成的哈希,会在悄无声息间使它触及的每一条基线失效。

因为产物名称是推导出来的,而不是被显式声明的,一次运行还会写出 `<output_dir>/manifest.json`:
每个被追踪的场景一行,记录它的测试、它的调用编号,以及它拥有的每一个文件。当你已经知道场景、
只想找到对应文件时,可以查阅这份清单。

> 一次调用的 `scenario:` 头部**不是**它的显示名称。一个 `parametrize` 的 id 会把参数插值进
> 测试的显示名称里,所以这份产物——无值的那一份——改为用方法和调用编号来命名:
> `Equipment can be found #2`。只运行一次的测试保留它一直以来的显示名称,所以任何已提交的
> 已批准追踪都不会因此变动。*文件名*依然带着转换为 slug 的标签,因为这才是在磁盘上区分两次
> 调用的依据,而 `manifest.json`——同时也是携带值的产物的一份索引——会按 pytest 显示的样子来
> 命名这个场景。请把敏感信息挡在 parametrize 的 id 之外。

## 内容

```
scenario: Weekend trip settles with three transfers

- TripSettlementService.record_expense(trip_name, expense)
  - ExpenseValidator.ensure_valid(expense)
  - TripLedger.record_expense(trip_name, expense)
- TripSettlementService.settle_trip(trip_name) → value
  - TripLedger.expenses_of(trip_name) → value
  ~ fork [2]
    - BalanceCalculator.compute_balances(expenses) → value
    - StockService.check() → value
```

- **头部:** `scenario: <人性化的测试名>` + 一个空行。没有别的——没有结果,没有追踪
  id/名称,没有日期。一个会运行多次的测试的某一次调用,写作
  `scenario: <人性化的方法名> #<index>`——parametrize id 的参数永远不会出现在这里。
- **调用行:** `类名.方法名(参数名, 参数名)`——只有名字,按捕获顺序排列,每一层深度用两个
  空格缩进。
- **结果类型:** 非 `None` 的返回值渲染为 ` → value`;`None`/void 形状的返回:什么都不写;
  抛出的异常写作 ` !! 异常简单类型名`(类型属于结构;消息是一种值,永远不会出现);未匹配的
  进入写作 ` ?? incomplete`。
- **并发:** fork 分组渲染为 `~ fork [n]`,从被传播的上下文快照中采纳的工作(一个线程或
  `asyncio` task 在一个已激活的快照下接手工作)渲染为 `~ async [n]`,两者的成员都会**按
  `类.方法` 排序**——跨线程/task 的捕获顺序是调度器的选择,不是行为的一部分,所以这份产物
  只表达并发工作的集合与嵌套关系,而绝不表达它们的顺序。async 分组按发起它们的 span 分组
  归类,所以一次调用的每一个 async 子节点都属于同一个组,并且当工作的存续超过了调用者时,
  它们也会出现在根层级。fire-and-forget 的工作渲染为 `~ fire-and-forget` 加上其子节点。线程
  名称/id 永远不会出现。
- **设计上排除的内容:** 所有的参数/返回值、异常消息、耗时、时间戳、线程身份、追踪/span id、
  追踪名称、运行结果,以及叙事文本(已解析的叙事会内嵌值)。
- **编码:** UTF-8、LF、末尾换行。标识符会经过控制字符净化处理。

## 保证

1. **确定性:** 相同的行为 ⇒ 字节级完全相同的文件。这正是让这份产物能够作为已批准追踪的基线、
   以及一致性夹具的 golden 格式的原因。
2. **无值:** 零提示注入接触面,零 PII,token 数量最少——默认就可以安全地交给一个 AI agent。
3. **职责分离:** 这份产物断言的是行为的*形状*;值的正确性依然是测试断言的职责。一个只改变
   返回值、而结构完全相同的变更,不会改变这份产物——这是刻意的设计。

## 已知缺口

这个实现目前还没有发出某些其他实现所提供的那种无值 JSON 姊妹文件
(`<test>.structural.json`,一个所有值都被剔除、形状类似 `.canonical.json` 的数组)——上面的
`.nt` 文本格式是这个实现今天唯一的结构化产物。已记录为后续工作;`.canonical.json`(携带值的
JSON 条目数组)不受影响,依然携带完整细节。

在本仓库中由 `narrativetrace.render.structural.StructuralTraceRenderer` 实现,由
`narrativetrace-pytest` 插件在 `.md`/`.json`/`.mmd` 伴生文件旁一并写出——参见
[pytest 插件指南](pytest插件指南.md)、[配置指南](配置指南.md)和[应提交的内容](应提交的内容.md)。
