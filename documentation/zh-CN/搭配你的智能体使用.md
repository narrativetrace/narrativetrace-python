# 搭配你的智能体使用 NarrativeTrace

NarrativeTrace 随附[智能体技能](智能体技能.md)——智能体用来安装本库、阅读追踪并诊断安装情况的操作步骤——
采用开放的 Agent Skills 格式。下表中的每个平台都已经能发现 `init` 写在 `.agents/skills` 下的页面,
所以只有一套页面,没有按平台分别准备的副本。各平台之间的差别在于:外部的人如何把这些页面放进项目,
以及哪个小文件会在智能体想起来去找之前就把它指向这些页面。

## `init` 写入的指引文件

指引文件是平台本来就最先读取的一个小文件。只有当项目表明该平台在使用时才会写入,它绝不是技能页面的
副本,也绝不会通过符号链接写入:

- **Cursor** —— `.cursor/rules/narrativetrace.mdc`,一条始终生效的规则,说明技能放在哪里;只有当项目
  有 `.cursor/` 目录时才会写入。Cursor 插件附带同一条规则。
- **Replit** —— `replit.md` 里一段带标记的 NarrativeTrace 小节,`replit.md` 是 Replit 智能体最先读取的
  项目记忆;只有当项目有 `replit.md` 或 `.replit` 时才会写入。它与 `AGENTS.md` 所带的小节相同,标记也
  相同。
- **Antigravity、GitHub Copilot、Claude Code** —— 没有指引文件。它们直接读取 `.agents/skills` 和
  `AGENTS.md`(Antigravity 将 `AGENTS.md` 作为规则加载;Claude Code 还会读取 `.claude/skills`,`init` 会为每个项目写入它)。

一个与 `init` 将要写入的内容完全相同的指引文件会被采纳而不是被拒绝;不属于我们的文件在没有 `--force`
时会被拒绝;`uv run narrativetrace uninstall` 恰好移除它写入的那些指引文件。
`uv run narrativetrace doctor` 会把每个检测到的平台的指引报告为存在且最新,或者指出缺了什么、
哪里过期、哪里不是我们写的。

## 手动复制

复制适用于任何平台,并且是没有自己的 `narrativetrace` 命令的智能体的唯一途径:

- **Codex**:目录会渲染出
  [`.agents/skills/narrativetrace-doctor/`](../../.agents/skills/narrativetrace-doctor/SKILL.md)
  以及同一文件夹中其余的技能目录——这是 Codex CLI 为项目自身技能所记录的布局。它的 frontmatter 只带
  `name` 和 `description`(Codex 没有记录 `when_to_use` 或 `allowed-tools` 这两个键);页面正文完全
  相同。把所需目录复制到你自己项目的 `.agents/skills/<名称>/` 下,Codex 就会用同样的方式识别它。
- **Antigravity**:工作区技能从 `.agents/skills/`(旧的 `.agent/skills/`)读取,所以同样的复制在 IDE
  和 `agy` CLI 中都适用。它的插件安装器只读取插件顶层的 `skills/` 目录,而本仓库没有提供,所以没有
  `agy plugin install` 这条路径。
- **任意智能体、任意平台**:任何会读取 `AGENTS.md` 的智能体都会看到 `init` 写在那里的常驻小节——
  技能的名称和描述——这样即使某个智能体从未想过要去找,它也知道这些技能的存在。

## 证据

每个平台的那一行都会指明支撑它的试验。Claude、Codex、Antigravity 和 Cursor 通道会在一个示例项目上,用真实
的命令行智能体运行安装提示;CLI 没有安装的通道会用一行说明跳过,而不是失败;Replit 和 GitHub Copilot
是由所有者记录的手动试验。这些通道、偶发配额策略和晋级矩阵的说明见
[Tier B——LLM 试验](../../packages/narrativetrace-skills-catalogue/evals/README.md)。
