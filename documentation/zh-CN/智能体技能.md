# 智能体技能

*(since 0.1.2, unreleased)*

NarrativeTrace 提供**技能(skills)**:可由智能体加载的流程,执行经过测试的命令,并以 `verify`
步骤作为完成的判定标准,而不是一份智能体可能读也可能不读的文档。技能被设计得很"薄"——检查、
诊断或生成的逻辑都放在经过测试的库代码里;技能本身的工作只是知道何时该出手、调用那些经过测试
的代码,并在上下文中解读结果。

## 两个技能:配置与诊断

- **`add-narrative-tracing`** —— 把 NarrativeTrace 安装到一个项目中,并带它走到第一条追踪:
  用真实的工具链安装(`uv add narrativetrace`)、包装一个对象、渲染并运行第一条追踪,然后接入
  一个真正的日志系统(标准库 `logging` 桥接)。最后运行 `uv run narrativetrace doctor` 并把
  接力棒交出去——这是两个技能之间的接缝。
- **`narrativetrace-doctor`** —— 仅用于诊断,并且**只读**:它从不编辑、生成或删除文件。运行经过
  测试的 CLI,读取它的报告,并处理那些单纯的 CLI 输出本身无法覆盖的部分:在测试中证明脱敏确实
  生效、在做断言之前先阅读一条渲染出的追踪,以及审批追踪流程(标记为"尚未研究"——它自己的评估
  用例仍待完成)。

它们相互配合:一个全新的项目从 `add-narrative-tracing` 开始;一个已经安装了 NarrativeTrace、但
有些地方不对劲的项目,从 `narrativetrace-doctor` 开始。两条路径最终都会走到 doctor——诊断从此
由它负责。之后会有一个技能负责生成(编写脱敏证明测试,这是今天 doctor 只能要求你添加、却不能
代劳的事)。

## `narrativetrace` 命令行工具

两个技能都会运行 `uv run narrativetrace doctor`——免费 CLI 的 `doctor` 命令,与已有的
`narrativetrace-approve` 控制台脚本并列。只读、零网络访问,`--json` 提供机器可读的输出,退出码
`0`(干净)、`1`(有发现项)或 `2`(无法运行)。十一项带有稳定、点分 id 的检查:解释器/pytest
版本是否符合声明、八个 `narrativetrace-*` 包是否统一在同一版本、`NARRATIVETRACE_OUTPUT` 的拼写
是否正确、pytest 插件的注册状态、`narrativetrace.toml` 中是否有无法识别的键、一个被导入却从未
使用的脱敏标记、`*args` 方法的参数是否坍缩成了单个 `args: [...]` 值、脱敏是否在测试中得到证明,
以及过期的审批追踪差异。

## 安装它们

- **Claude Code**:渲染好的 `SKILL.md` 文件位于本仓库的
  [`.claude/skills/add/`](../../.claude/skills/add/SKILL.md) 和
  [`.claude/skills/doctor/`](../../.claude/skills/doctor/SKILL.md)。把任意一个目录复制到你自己
  项目的 `.claude/skills/<name>/` 下,Claude 会自动识别它;一旦打包成插件,就可以用
  `/narrativetrace:add` / `/narrativetrace:doctor` 调用,也可以直接按名字
  (`add-narrative-tracing` / `narrativetrace-doctor`)调用。
- **任意智能体、任意平台**:每一个读取 `AGENTS.md` 的智能体都会看到本仓库自己的 `AGENTS.md` 在
  其 `<!-- narrativetrace:skills:start -->` 标记之间携带的常驻提示——两个技能的名称和描述都在
  其中,所以即便一个智能体从未想到要去查找它们,也依然知道它们的存在。
- **Codex、Gemini 以及自动安装器**已在路线图上,但尚未构建——今天,复制渲染好的文件就是可行
  的路径。

## 它们是如何构建的

两个技能都从不手工编辑。
`packages/narrativetrace-skills/src/narrativetrace_skills/catalogue/add_narrative_tracing.py`
和 `.../catalogue/narrativetrace_doctor.py` 是唯一的两个真相来源;`python
scripts/skills_render.py --fix` 会据此重新生成 `.claude/skills/add/SKILL.md`、
`.claude/skills/doctor/SKILL.md` 以及本仓库自己 `AGENTS.md` 中的那一段,而 `python
scripts/skills_render.py --check`(已接入 `uv run poe check`)只要这三者中任何一个与类型化的
源不同步,就会让构建失败。渲染出的页面展示的每一段代码,都通过本仓库其他文档已经在用的同一套
`<!-- snippet: -->` 标记约定,从真实、经过测试的源码中嵌入——绝不是手写的示例。一项 Tier A 检查
会把对私有规划笔记的引用挡在两份页面之外:说明性的句子可以保留,指名笔记的引用则不行。

## 评估它们

`packages/narrativetrace-skills/evals/` 承载了 Tier B 套件(触发短语、每个技能一个"顺利路径"
用例、doctor 脱敏检查的一个偏差用例)——从不由 `poe check` 运行;由负责人手动执行,或从夜间任务
中执行,通过订阅制的 CLI,绝不使用按量计费的 API。关于 Codex/Gemini 的间歇性通道策略以及晋升
矩阵,参见[它自己的 README](../../packages/narrativetrace-skills/evals/README.md)。
