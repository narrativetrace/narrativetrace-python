# 故障排查

症状 → 原因 → 解决方法,针对人们实际会遇到的失败模式收录。有些条目是完整的解释;另一些则指向
已经更详细讲解过这件事的指南,而不是在这里重复——一件事只有一个归宿。

## 没有追踪输出文件

**原因:** 产物输出默认是关闭的。

**解决方法:** 设置 `NARRATIVETRACE_OUTPUT=1`(或者在 `narrativetrace.toml` / `pyproject.toml` 的
`[tool.narrativetrace]` 表中设置 `output = true`)——见[配置指南](配置指南.md)。一个空追踪
(其方法从未被调用过的被包装对象)即使开启了输出也不会写出任何内容;没有空文件可找。

## 我在终端里看不到逐测试的追踪

**原因:** 逐测试的 “Execution trace” 回显是用普通的 `print()` 写出的,而 pytest 默认会捕获标准
输出——一次普通的 `pytest` 运行在你的终端上什么都不显示,即使 `narrative-traces/` 下的文件已经
被正确写入。

**解决方法:** 加上 `-s`(`pytest -s`)运行以实时查看,或者直接查看文件。套件页脚摘要
(`NarrativeTrace — Suite complete …`)总会打印出来,不受此影响,因为它走的是 pytest 的
`pytest_terminal_summary` 钩子,绕过了捕获机制。

## 一个带 `*args` 的方法的参数显示为单个 `args: [...]` 值

**原因:** `inspect.signature` 能为普通签名绑定参数名,但一个接受 `*args` 的方法没有逐参数的
名字可读——没有可供重建的命名信息,因为 Python 自身就没有这些信息。

**解决方法:** 添加 `@traced("first", "second", ...)` 来显式提供名字:

```python
from narrativetrace import traced

class Calc:
    @traced("a", "b")
    def add(self, *args):
        return sum(args)
```

## `trace_object` 包装了它,但调用依然没有被追踪

**原因:** 你在某处持有一个指向*原始*未包装对象的引用——`trace_object` 会返回一个新的 wrapper;
你传入的对象本身不会被改变。在那个原始引用上发起的调用,或者在一个未被追踪的方法内部通过 `self`
发起的调用,都会完全绕过 wrapper。

**解决方法:** 确保每一个调用方持有的都是 `trace_object(...)` 返回的对象,而不是你自己构造的那个。
通常这意味着只在一个组合根或一个 fixture 处包装一次,然后把这个被包装的引用一路传递下去。

## 跨线程或跨 task 的追踪是空的,或者一个被 fork 出来的子任务显示为一个新的根节点

**原因:** `ContextVarNarrativeContext` 在设计上会隔离线程*和* asyncio task——提交给线程池或作为
task 启动的工作,只有在收到一个上下文快照,或者经过 `ForkJoinGroup`/`FireAndForgetGroup` 时,才会
并入父级追踪。一个两者都没收到的 worker 会记录到它自己独立的上下文中。另外:直接在一个被追踪的
`async def` 方法内部执行 fork,会通过*同步*调用栈来解析父级,而这个栈在协程内部是空的,因此以这
种方式启动的子任务会以同级/根节点的身份出现,而不是嵌套在 `async` 调用方之下——这是一个已知且
仍未解决的缺口。

**解决方法:** 在边界处显式获取一份快照,或者从一个同步方法(或一个基于线程池的方法)中使用
`ForkJoinGroup.create(...)` / `FireAndForgetGroup.create(...)`,而不是直接在 `async def` 内部使用。
如果你只需要被 fork 出来的那部分工作自己的追踪,就在那个记录了它的线程或 task 内部,在 task 里
调用 `capture_trace()`。

## 清晰度评分看起来不对

**原因:** 通常是评分器标记出的一个泛化命名——`get`、`set`、`process`、`handle`、`data`、
`info`、`temp` 及类似名称无论上下文如何都会得低分;一个你的团队认可为领域词汇、但内置词典不认识
的名字,会被当作未知词汇评分,而不是领域专属词汇。

**解决方法:** 查看 `clarity-report.md` 中的问题列表,然后要么重命名(`getData()` →
`fetchOrderHistory()`),要么通过一个已提交的 `glossary.json` 教会评分器你的词汇——见
[清晰度指南](清晰度指南.md)。

## 启动时出现 `DuplicateConfigurationError`

**原因:** 同一个目录里同时存在 `narrativetrace.toml` 和带 `[tool.narrativetrace]` 表的
`pyproject.toml`。配置解析拒绝悄悄地选择其中一个。

**解决方法:** 每个目录只保留一个配置来源——删除或合并其中一个。见
[配置指南](配置指南.md)。

## ASGI 中间件没有捕获我期望它跳过的一条路由,或者跳过了我期望被捕获的一条

**原因:** `excluded_paths` 按请求路径的精确字符串比较,而不是 glob 或前缀匹配——排除 `/health`
并不会排除 `/health/live`,而且只有 HTTP 作用域会被捕获(WebSocket 和 lifespan 作用域始终原样
通过)。

**解决方法:** 显式列出每一个你想排除的路径,或者在中间件运行之前,在你自己的路由层里更早地做
匹配。见 [FastAPI与ASGI指南](FastAPI与ASGI指南.md)。

## 一个我以为会被脱敏的值出现在了追踪里

**原因:** 拒绝列表按*字段名或参数名*匹配,而不是笼统地匹配“所有叫 `data` 的东西”——一个存放
在拒绝列表不认识的名字下(且从形状上看不像 JWT、卡号、`Set-Cookie` 字符串或国民身份证号)的值,
默认不会被脱敏。另外:一个 `{param.path}` 叙述模板始终检查*默认*拒绝列表,即使周围的 `ValueRenderer` 是用
自定义或已禁用的 `RedactionPolicy` 为普通参数渲染而构建的——这是一个已记录的局限,不是缺陷。

**解决方法:** 用 `@not_traced(...)` / `not_traced_field(...)` 显式标记该成员——显式标注无论策略
如何都始终优先。完整、经过验证的契约见[隐私与脱敏](隐私与脱敏.md)。
