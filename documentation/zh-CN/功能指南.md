# NarrativeTrace 功能指南(Python)

NarrativeTrace for Python 实际提供了什么,从使用者的视角来看。要查看完整的跨平台功能目录(所有层级、所有
平台),请参见权威功能指南:
<https://github.com/narrativetrace/narrativetrace-java/blob/main/documentation/feature-guide.md>。

**状态标签**(与权威指南使用相同的词汇):

- **免费** —— 已发布,在本仓库中可用,采用 Business Source License 1.1(见下方*许可*)。
- **Pro** —— 在 NarrativeTrace Pro 中发布(商业层,单独的发行版)。
- **开发中** —— 正在积极构建;设计已经确定。
- **已规划** —— 已明确规格,尚未开始;可能会变化。

**许可。** NarrativeTrace 的 API 和输出格式是开放标准(Apache 2.0)。它的运行时是免费且源代码
可见的(BSL 1.1,在每个版本发布四年后转为 Apache 2.0)。Pro 是商业化的。这里标记为**免费**的
一切都属于这个运行时:可免费用于生产环境、源代码可见、但不是开源——根目录的
[`LICENSE`](../../LICENSE) 是权威依据。

按主题划分的文档位于 [guides/](../guides)。Python 特有机制*为什么*这样设计——包括被否决的
备选方案——记录在一份内部决策日志中,不在此公开。

## 记录你代码的故事(核心追踪)

| 功能 | 状态 | 备注 |
|---|---|---|
| 自动叙事捕获——方法、类、参数名,返回值,耗时,错误;零日志语句 | 免费 | `trace_object(obj, context)` + `ContextVarNarrativeContext`;名字通过 `inspect.signature` 读取 |
| 增强装饰器——`@narrated("… {param} …")`,可叠加的 `@on_error(ExcType, "…")`(最具体者优先),`@traced` 为 `*args` 提供名称覆盖,`@narrative_summary` | 免费 | [guides/decorators.md](装饰器指南.md) |
| 敏感数据脱敏——`@not_traced` 参数、`not_traced_field(...)` / `__nt_not_traced__` 字段、基于名称模式的脱敏(`RedactionPolicy`) | 免费 | 被脱敏的值渲染为 `[REDACTED]`,对标记的成员完全不读取;一条到达被脱敏成员的 `@narrated`/`@on_error` 模板路径,在路径的任意深度都会解析为同一个标记;`NamedTuple` 按字段名内省,而不是渲染成匿名的位置集合,因此一个被脱敏的字段在多一层容器内也照样保持隐藏 |
| 五个捕获级别(OFF → ERRORS → SUMMARY → NARRATIVE → DETAIL),运行时可更改,`NARRATIVETRACE_LEVEL` 环境变量通道 | 免费 | 级别名称与 Java 实现不同(SUMMARY/NARRATIVE 对应 NARRATIVE/FLOW)。参数值只在 DETAIL 存在;抑制发生在捕获阶段,而不是渲染阶段 |
| 双重门禁级别——捕获级别与日志级别相互独立 | 免费 | [guides/configuration.md](配置指南.md) |
| 并发捕获——`ForkJoinGroup` / `FireAndForgetGroup`,覆盖 asyncio task *以及* `ThreadPoolExecutor`,完整身份快照传播,跨 task 嫁接 | 免费 | 即使执行不是顺序的,故事依然保持连贯 |
| 双向传播——一个快照把追踪带*进*一个线程或 task,在那里被追踪的工作也会*传回来*:捕获栈从它被发布的那一刻起就会报告它,并跨越一整串 async 跳转链条传播 | 免费 | 放置位置遵循提交时间;被采纳的工作被标记为 `ConcurrencyKind.ASYNC`;会重新发出自己子节点的辅助函数可通过 `activate_without_adoption()` 选择不参与;每个栈上限 10,000 个 span,超出上限的交接会被整体拒绝并通过 `TraceLoss` 报告 |
| 追踪身份——追踪 id、人类可读的追踪名称、故事/章节 id 推导 | 免费 | 与规范 schema 对齐 |
| 纯净性契约——内省只枚举已存储的数据;`@property` getter 从不执行;每个被调用的成员都是有边界且异常隔离的 | 免费 | [guides/decorators.md](装饰器指南.md) |
| 故障安全捕获——抛出异常的渲染器或导出器永远不会掩盖业务结果或异常(同步和 `async` 方法皆然) | 免费 | |

## 阅读这个故事(输出)

| 功能 | 状态 | 备注 |
|---|---|---|
| 缩进文本、Markdown 和散文渲染器 | 免费 | |
| 追踪值引用——对重复出现的已捕获值按内容寻址去重,附带可读标签(首次出现时 `‹Hotel›=full`,之后 `‹Hotel›`) | 免费 | `render.value_reference.ValueReferenceIndex`,通过 `MarkdownRenderer` 使用。标签来自结构化值的身份字段(name/id/description/…),绝不会来自一个被脱敏的字段;字节相等性用来判定是否相同;包含在其他已捕获值内部也会被计入并替换。仅限 Markdown |
| 追踪内值增量——同一实体的一次再捕获,如果发生了变化,会渲染为相对于参考值的一个 diff(`‹Dinner›′{amount: 100.0→92.0, currency: "USD"→"EUR"}`) | 免费 | `render.value_delta.value_delta`。“同一实体”指相同的结构化类型名加上相等的身份字段;只对发生变化的标量字段生效(`StringVal`/`IntVal`/`FloatVal`/`BoolVal`/`InstantVal`/`NullVal`),绝不会从结构化树重新构建。一个发生变化的嵌套对象或列表、一个不同的字段集合,或一个没有身份字段的值,依然会完整渲染,与之前完全一样。一个自身又重复出现的、发生了变化的变体,其定义本身就是这个 diff(`‹Dinner·2›=‹Dinner›′{…}`)。仅限 Markdown |
| 逐测试的追踪文件,附带 `.json` 和 Mermaid `.mmd` 伴生文件 | 免费 | 默认开启 *(since 0.1.2, unreleased)*,`NARRATIVETRACE_OUTPUT=false` 可关闭;空追踪不写出任何内容 |
| 面向 AI 安全的结构化追踪产物(`.nt`)——无值形式、按调用命名、`manifest.json`、绿色基线搭配套件页脚上的一行差异摘要 | 免费 *(since 0.1.2, unreleased)* | `render.structural.StructuralTraceRenderer`;见[结构化追踪格式](结构化追踪格式.md) |
| 审批模式——已提交的 `.approved.nt` 追踪会在任何结构不一致时让测试带着可读的差异失败;`uv run poe approve` / `narrativetrace-approve` 会提升一份已审阅的已接收追踪 | 免费 *(since 0.1.2, unreleased)* | `NARRATIVETRACE_APPROVAL=true`;approval testing 的理念,应用到追踪上——见[应提交的内容](应提交的内容.md) |
| 规范 JSON 导出(事件流形式) | 免费 | `export_json` / `export_document_json`;经过往返测试,并且依据真实写入器落盘的字节,对照 `chapter-tree.schema.json` 做了 schema 校验 |
| 按服务的章节 schema(`nt.entryType` / `schemaVersion` / 故事-章节条目) | 免费 | `export_chapter_json`;对照 `chapter.schema.json` 校验。关联信息绝不会被省略:`trace_id` 是被采纳/继承/生成的,`nt.storyId` 回退到第一个根调用(`Class.method`,否则为 `unknown`),`nt.chapterId` 回退到故事,`nt.traceName` 回退到已解析的 id——因此即便一条没有任何 span 的追踪也依然能通过校验 |

| 功能 | 状态 | 备注 |

| 独立源码扫描器——`narrativetrace-clarity` 控制台脚本,无需测试 | 免费 | |
| 评分中的项目词汇——已提交的术语表扩展内置词典 | 免费 | 一个文件,一套评审流程:已提交的 `glossary.json` 中的动词按领域动词评分,其名词按领域 token 评分。从 `narrativetrace.glossary_dir` 读取(默认为工作目录),每个会话读取一次;读取是无条件的,不同于采集。内置层级保有权威——泛化动词、布尔前缀、无意义的占位词、废弃的同义词以及 `stale` 术语永远不会被提升 |
| 认可的缩写——`glossary.json` 中一个声明的根级 `abbreviations` 小节 | 免费 | Schema 2:`{"fx": "foreign exchange"}`。只有被列出的 token 才会停止被要求写出完整形式——出现在一个已提交术语*内部*的 token 则不会,所以 `calc total` 依然保留 `calc` → `calculate` 这条提示。归人类所有(采集永远不会写入它,合并会将它原样保留);为空时会被省略,因此一个不声明任何缩写的术语表在 schema 1 下保持字节级不变;读取方在任何版本下都能接受它 |
| 词汇采集——pytest 套件钩子(通过 `glossary.json` 是否存在来决定是否启用,`NARRATIVETRACE_GLOSSARY=off/on` 可覆盖该默认值),会合并新术语,并把废弃别名的使用标记为 `non-canonical-term` 清晰度问题,每一条都附带一个机械式改名建议 | 免费 | 只做增量式合并(人工编写的字段永远不会被覆盖);一份易变的 `glossary-usage.json` 会报告一次运行发现了什么,但永远不会被提交 |
| 静态术语表扫描——`glossary-scan` 控制台脚本,无需运行测试;这也是唯一会采集 `@narrated`/`@on_error` 叙事模板的地方(一条已捕获的追踪其值已经被插值,不再是模板) | 免费 | `narrativetrace-glossary`;一个刻意设计为需主动启用的写入工具,而不是 CI 门禁 |
| 可选的 CI 门禁——`--min-score`、`--max-high-issues` | 免费 | 建议默认使用仅告警模式 |

## Pro 层级(商业)

Python 的 Pro 层级以单独的商业发行版提供(专有许可,从不发布到
PyPI)。事件流聚合已于 2026-07-12(Phase 31a Stage 2)从本仓库的免费核心中迁移过去:
**`EventAggregator` —— Pro**。流程摘要、迁移 diff、依赖图,以及 MCP 工具处理器都是**已规划
(Pro,受限)**——其执行取决于该仓库私有实施计划(Phase E3–E5)中
按付费 Python 技术栈项目安排的进度。审计与合规**不计划**在 Python 上实现
(Phase E6)。

## 让这份指南保持诚实

改编自权威指南的规则:

1. NarrativeTrace for Python 的每一个用户可见功能都在这里出现且只出现一次,并带有一个状态。
2. 一个功能只有在被合并、测试且已文档化之后,才能变为**免费**/**Pro**。“开发中”意味着设计已经
   确定且工作已排期;“已规划”意味着仅仅完成了规格说明。
3. 新增或提升某个功能的改动,必须在同一个提交里更新本文件。
4. 本指南只覆盖 NarrativeTrace for Python 实际发布的内容。产品层面的功能及其跨平台状态位于权威指南中
   (链接见顶部)——不要在这里分叉它的行;只记录 Python 一侧的真实情况(包括诚实地记录差距)。
