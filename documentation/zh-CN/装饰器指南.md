# 装饰器

用 `trace_object` 包装一个对象会追踪它的每一个公共方法。装饰器可以精细控制捕获的内容以及呈现方式。

## 你已经导入了它——这样使用它

单单导入 `narrated` 或 `not_traced` 什么也做不到——两者都必须应用到一个真实的方法或参数上,
并且其效果必须用一条断言来证明。两者的最小搭配,叠加在同一个方法上,正是
`packages/narrativetrace/tests/test_trace_object.py` 里的 `AuthService` 已经在做的:

```python
from narrativetrace import (
    ContextVarNarrativeContext,
    ProseRenderer,
    narrated,
    not_traced,
    trace_object,
)


class AuthService:
    @narrated("login attempt for {username} with {password}")
    @not_traced("password")
    def login(self, username: str, password: str) -> str:
        return f"session-for-{username}"


def run() -> str:
    """Traces one login and renders the result -- `password` never reaches it, in the argument
    list or in the narration template that names it."""
    context = ContextVarNarrativeContext()
    service = trace_object(AuthService(), context)
    service.login("alice", "hunter2")
    return ProseRenderer().render(context.capture_trace())
```

```text
The trace damp shard sways:

The auth service login — login attempt for alice with [REDACTED], returning "session-for-alice".
```

证明它的断言:`assert "[REDACTED]" in rendered`——`password` 永远不会出现在 `@narrated` 围绕它
构建的叙述文本里,旁边的一条断言还会检查未被脱敏的参数 `username` 依然存在
(`examples/test_import_and_use.py`)。

`uv run narrativetrace doctor` 正是在项目自身的源码里监视这种失效模式:**`trap.silent-sink`**
会标记出下文中被导入或声明、却从未真正应用的字段级脱敏接触面(`not_traced_field`、
`__nt_not_traced__`)——对一个真实字段调用 `not_traced_field(...)`,或者在 `__nt_not_traced__`
中列出真实的字段名,然后通过在渲染后的追踪里断言 `"[REDACTED]"` 来证明它——而
**`trap.redaction-proof`** 会标记出没有任何测试断言字面量 `[REDACTED]` 标记的项目。下文详细介绍
这两个装饰器,以及两种字段级脱敏接触面。

## `@narrated` —— 散文式叙述

```python
from narrativetrace import narrated

class InventoryService:
    @narrated("reserves {quantity} of {product_id}")
    def reserve(self, product_id: str, quantity: int) -> Reservation:
        ...
```

模板占位符 `{name}` 以及带一级句点的 `{customer.address}` 会根据参数值解析;更深的路径如
`{customer.address.city}` 永远无法解析,会在运行时原样保留,因此即便有占位符引用它,也仍会在
套件中触发一条“占位符未解析”警告。

**脱敏优先于引用它的模板。** 一个到达已脱敏成员的路径——无论在路径的哪个深度,而不只是最后一
段——都会解析为 `[REDACTED]`,而不是值本身或字面占位符。一个直接引用某个值的裸占位符 `{name}`
同样遵循这两条规则:拒止名单会像检查字段名一样检查这个键名,值本身的形态也会被检查,因此
`@narrated("login {password}")` 和以 `{value}` 形式出现的 JWT 都会渲染为 `[REDACTED]`。无论是在
路径中引用某个字段,还是引用某个值,都永远不会削弱直接作用于该值的规则:如果你确实需要在叙事中
看到这个值,请从该成员上移除 `@not_traced`;这个移除
本身就是一次刻意的、可评审的决定,并且会出现在 diff 中。

## `@on_error` —— 失败上下文

可叠加;为匹配的异常类型,在失败退出处附加一条已解析的消息:

```python
from narrativetrace import on_error

class PaymentService:
    @on_error(TimeoutError, "gateway timed out charging {customer_id}")
    def charge(self, customer_id: str, amount: int) -> Payment:
        ...
```

## `@not_traced` —— 脱敏

按名称脱敏一个参数:

```python
from narrativetrace import not_traced

class AuthService:
    @not_traced("password")
    def login(self, username: str, password: str) -> Session:
        ...
```

脱敏作为参数传入的对象上的某个**字段**,有两种方式:

- **`not_traced_field(...)`** —— 一个 dataclass 字段,通过它自己 `field()` 的元数据来标记。
- **`__nt_not_traced__`** —— 一个类属性,列出要脱敏的字段名,适用于任何 `field(metadata=...)`
  用不上的其他类型对象:普通类、`NamedTuple`,或者 attrs 类。它是从**类**上读取的一个字段名
  元组/列表/集合(`is_field_not_traced` 会先检查它,再检查 dataclass 元数据),因此子类会继承它,
  而实例无法覆盖它。

两者的脱敏效果完全相同——按字段逐一脱敏,而不是整个容器对象——并且无条件地优先于任何策略:

```python
from dataclasses import dataclass

from narrativetrace import (
    ContextVarNarrativeContext,
    IndentedTextRenderer,
    not_traced_field,
    trace_object,
)


@dataclass
class Credentials:
    username: str
    secret: str = not_traced_field(default="")


class LegacyCredentials:
    """A plain (non-dataclass) class: `__nt_not_traced__` names the fields to redact."""

    __nt_not_traced__ = ("secret",)

    def __init__(self, username: str, secret: str) -> None:
        self.username = username
        self.secret = secret


class AuthService:
    # Parameter named `account`, not `credentials` -- the latter is itself on the name-based
    # deny-list (see documentation/privacy-and-redaction.md) and would redact the whole argument
    # regardless of which fields inside it are marked `@not_traced`.
    def login(self, account: Credentials | LegacyCredentials) -> str:
        return f"session-for-{account.username}"


def run() -> str:
    """Traces two logins, one per redaction surface, and renders the result."""
    context = ContextVarNarrativeContext()
    service = trace_object(AuthService(), context)
    service.login(Credentials("alice", "hunter2"))
    service.login(LegacyCredentials("bob", "hunter2"))
    return IndentedTextRenderer().render(context.capture_trace())
```

运行 `python -m examples.not_traced_fields` 会打印(`0ms` 因机器而异,与 60 秒页面一样):

```text
AuthService.login(account: Credentials(username="alice", secret=[REDACTED])) → "session-for-alice" — 0ms
AuthService.login(account: LegacyCredentials(username="bob", secret=[REDACTED])) → "session-for-bob" — 0ms
```

被脱敏的值在渲染之前就会被替换为一个标记——它们永远不会到达渲染器、导出器或日志。

## 纯净性契约——追踪期间的副作用

NarrativeTrace 在渲染一条追踪时,可能会在你的对象上调用一小组固定的代码路径。请保持这些成员
**纯净**——不带有诸如惰性加载、访问计数、缓存填充或 I/O 之类的副作用——就像你会为调试器或
序列化器所做的那样。

哪些会被调用,哪些不会:

- **内省枚举的是已存储的数据,而不是代码。** 字段名来自 `dataclasses.fields()`、attrs 的元数据、
  `NamedTuple` 的 `_fields`,或者实例的 `__dict__`/`__slots__`——因此一个计算型的 `@property`
  (其 getter 可能会计数访问次数或惰性加载)永远不会在内省过程中被枚举,也永远不会被执行。
  `NamedTuple` 是按字段名内省的,而不是渲染成一个匿名的位置值列表,所以一个被脱敏的字段会像
  dataclass 字段一样保持隐藏。
- **你自己的类型,其自定义 `__str__` 永远不被信任** *(since 0.1.2)*。任何携带实例状态的对象——
  dataclass、attrs 类、`NamedTuple`,或者拥有非空 `__dict__`/`__slots__` 的普通对象——都会被逐字段
  内省,无论它是否还定义了 `__str__`/`__repr__`;那个手写的方法永远不会被采纳,就像它在
  dataclass 上从来不会被采纳一样。修复之前,一个普通类只要定义了自定义 `__str__` 就会直接凌驾于
  内省之上,于是一个会插入敏感字段的手写 `__str__`——无论是直接插入,还是通过一个嵌套对象自身的
  `__str__` 间接插入——都能完全绕过脱敏;dict/map 的键存在一模一样的漏洞(裸露、未经中介的
  `str(key)`),现在以同样的方式被堵上:键会像值一样被内省并接受脱敏检查。当你想给复合类型一个
  精心编排的单行摘要、而不是逐字段的默认渲染时,给它一个 `@narrative_summary` 方法——这个机制不受
  影响,依然是控制具体展示内容的受支持方式。
- **没有声明任何字段同样换不来信任** *(since 0.1.3, unreleased)*。一个内省看不见其状态的值——把
  字段放在 C 结构体里的 `ctypes.Structure` 子类或扩展类型,把状态放在以身份为键的模块级表或闭包
  里的类——过去会被当作叶子值,通过自己的 `__str__`/`__repr__` 渲染,而那段文本可以越过拒绝列表
  把这些字段打印出来。现在它只渲染为自己的类型名(`<CStructCredentials>`):可见、有界、未被读取。
  标准库自身的值类型(`pathlib.Path`、`datetime`、`uuid.UUID`、`decimal.Decimal`、`Enum` 成员……)
  依然以自己的简短文本渲染——这份信任由来源决定,除此之外别无他据。
- **抛出异常的摘要、`__str__` 或 getter 会渲染一个带类型的错误标记,绝不会渲染它自己的消息**
  *(since 0.1.2)*。`<error: ValueError>`、`<error: RecursionError>` 等等——只为失败的那一部分替换成异常自身的类型名
  (绝不是整条追踪,也绝不是裸露的 `<error>`)。异常的*消息*被刻意地永远不渲染:消息里可能带着
  那个渲染失败的值本身(`"summary failed for {token}"` 否则就会泄露 `token`),所以只有类型名——
  绝不是 `str(exc)`——会到达输出。
- **集合只有在是平台定义的类型时才会被枚举。** `list`/`tuple`/`dict`/`set`/`frozenset` 通过自身
  的状态枚举;它们的子类则通过那个祖先类型自身的状态读取来枚举,绝不会走子类重写过的
  `__iter__`/`items`。手写的集合(从零实现 `Collection` 协议、没有平台祖先)同样不会被枚举——
  它会像普通对象一样逐字段渲染。一个不是完整 `Collection`(缺少 `__contains__`)的简单可迭代对象
  会渲染成它的类型名加尺寸,绝不是它的元素,并且它的 `__iter__` 永远不会被触碰。唯一的例外是下面
  的 `__narrative_elements__` 钩子。
- **`__narrative_elements__` 是唯一被信任、可以枚举自身元素的钩子。** 详见下文。
- **调用是有边界且隔离的。** 输出有上限(字符串长度、集合项数、深度);一个抛出异常的 `__str__`、
  摘要或 getter 永远不会导致被追踪的业务调用失败(模板会回退到字面占位符 `{placeholder}`);值是
  在调用点被立即渲染的,因此任何副作用只会发生一次,且发生在一个确定的时间点。Future 和
  awaitable 永远不会被强制求值。

## `__narrative_elements__`——受信任的迭代

第三个被认可的渲染钩子,与 `@narrative_summary` 以及平台值自身的 `__str__` 并列:一个声明
了无参数方法 `__narrative_elements__` 的类型,会被信任通过该方法枚举自身的元素——这是渲染唯一
会执行某个类型自身迭代逻辑的情形,因为作者已经声明了它是纯净的。

```python
class OrderLine:
    def __init__(self, items: list[Item]) -> None:
        self._items = items

    def __narrative_elements__(self) -> list[Item]:
        return list(self._items)
```

渲染后的 `OrderLine` 会展示它的条目(采用与普通集合相同的条目数上限,超出时同样使用
`… (N total)` 标记),而不是它的 `_items` 字段名。这个方法在与其他钩子相同的反射渲染保护下运行:
它对某个被追踪对象发起的调用不会开启任何 span。抛出异常的 `__narrative_elements__` 会像其他任何
钩子失败一样,退化为同样带类型的 `<error: TypeName>` 标记,绝不会退化为对象的真实字段。

当一个手写的集合类型(没有平台祖先可以依赖,原本只会渲染成普通对象)拥有值得直接展示的元素时,
就使用它——这与 `@NarrativeElements` 在其他 NarrativeTrace 运行时中扮演的角色相同。

如果一个成员无法保持纯净,就用 `@not_traced` / `not_traced_field(...)` 标记它——被脱敏成员的值
永远不会被读取——或者为该类型提供一个 `@narrative_summary`,让你能精确控制到底访问了什么(精心
设计的 `__str__` 不再能让一个复合类型跳出内省,见上文)。在 `NARRATIVETRACE_LEVEL=OFF` 时(以及
在 `SUMMARY` 级别下的参数值),完全不会发生任何参数渲染。
