# 装饰器

用 `trace_object` 包装一个对象会追踪它的每一个公共方法。装饰器可以精细控制捕获的内容以及呈现方式。

## `@narrated` —— 散文式叙述

```python
from narrativetrace import narrated

class InventoryService:
    @narrated("reserves {quantity} of {product_id}")
    def reserve(self, product_id: str, quantity: int) -> Reservation:
        ...
```

模板占位符 `{name}` 以及带一级句点的 `{customer.address}` 会根据参数值解析;更深的路径如
`{customer.address.city}` 永远无法解析,会在运行时原样保留,因此即便有占位符引用它,也仍会在
套件中触发一条“占位符未解析”警告。

**脱敏优先于引用它的模板。** 一个到达已脱敏成员的路径——无论在路径的哪个深度,而不只是最后一
段——都会解析为 `[REDACTED]`,而不是值本身或字面占位符。一个直接引用某个值的裸占位符 `{name}`
同样遵循这两条规则:拒止名单会像检查字段名一样检查这个键名,值本身的形态也会被检查,因此
`@narrated("login {password}")` 和以 `{value}` 形式出现的 JWT 都会渲染为 `[REDACTED]`。无论是在
路径中引用某个字段,还是引用某个值,都永远不会削弱直接作用于该值的规则:如果你确实需要在叙事中
看到这个值,请从该成员上移除 `@not_traced`;这个移除
本身就是一次刻意的、可评审的决定,并且会出现在 diff 中。

## `@on_error` —— 失败上下文

可叠加;为匹配的异常类型,在失败退出处附加一条已解析的消息:

```python
from narrativetrace import on_error

class PaymentService:
    @on_error(TimeoutError, "gateway timed out charging {customer_id}")
    def charge(self, customer_id: str, amount: int) -> Payment:
        ...
```

## `@not_traced` —— 脱敏

按名称脱敏一个参数,或者通过类属性 / dataclass 元数据脱敏一个字段:

```python
from dataclasses import dataclass, field
from narrativetrace import not_traced, not_traced_field

class AuthService:
    @not_traced("password")
    def login(self, username: str, password: str) -> Session:
        ...

@dataclass
class Credentials:
    username: str
    secret: str = not_traced_field(default="")   # 或者:__nt_not_traced__ = ("secret",)
```

被脱敏的值在渲染之前就会被替换为一个标记——它们永远不会到达渲染器、导出器或日志。

## 纯净性契约——追踪期间的副作用

NarrativeTrace 在渲染一条追踪时,可能会在你的对象上调用一小组固定的代码路径。请保持这些成员
**纯净**——不带有诸如惰性加载、访问计数、缓存填充或 I/O 之类的副作用——就像你会为调试器或
序列化器所做的那样。

哪些会被调用,哪些不会:

- **内省枚举的是已存储的数据,而不是代码。** 字段名来自 `dataclasses.fields()`、attrs 的元数据、
  `NamedTuple` 的 `_fields`,或者实例的 `__dict__`——因此一个计算型的 `@property`(其 getter 可能
  会计数访问次数或惰性加载)永远不会在内省过程中被枚举,也永远不会被执行。`NamedTuple` 是按字段
  名内省的,而不是渲染成一个匿名的位置值列表,所以一个被脱敏的字段会像 dataclass 字段一样保持
  隐藏。
- **NarrativeTrace 确实会调用的:** 自定义的 `__str__`、`@narrative_summary` 方法,以及你在
  `@narrated`/`@on_error` 模板中引用的任何属性路径——`{order.total}` 通过 `getattr` 解析,因此在
  那里被引用的 `@property` *会*执行其 getter。
- **调用是有边界且隔离的。** 输出有上限(字符串长度、集合项数、深度);一个抛出异常的 `__str__`
  或 getter 永远不会导致被追踪的业务调用失败(模板会回退到字面占位符 `{placeholder}`);值是在
  调用点被立即渲染的,因此任何副作用只会发生一次,且发生在一个确定的时间点。Future 和
  awaitable 永远不会被强制求值。

如果一个成员无法保持纯净,就用 `@not_traced` / `not_traced_field(...)` 标记它——被脱敏成员的值
永远不会被读取——或者为该类型编写一个精心设计的 `__str__` / `@narrative_summary`,让你能精确
控制到底访问了什么。在 `NARRATIVETRACE_LEVEL=OFF` 时(以及在 `SUMMARY` 级别下的参数值),完全
不会发生任何参数渲染。
